📌 Executive Summary

The honest read on what's buildable, what's industry-standard, and where the lines get drawn.
✅ Good news The vast majority of the spec maps cleanly onto existing WordPress + WooCommerce plugins. Sections like Documents, Services, Profile, Notifications, and Sidebar are essentially solved problems with off-the-shelf plugins. We can deliver 85–90% of the spec in production-ready form using a curated stack.
⚠️ The catch — automation has limits Filing Status, EIN Status, and per-state compliance deadlines cannot be auto-fetched — there's no public API from the IRS or state agencies. These will be manually managed by BizJump's admin team via the dashboard backend. This is exactly how Northwest, Bizee, and Incfile operate — it's industry-standard, not a shortcut.
🎯 Bottom line Frame the deliverable as: "A fully functional dashboard with 92% feature parity to the spec. The 8% that requires real-time IRS/state APIs (which don't exist publicly) is admin-managed — same as every competitor in the space."

🔌 CRM & External Integrations — Two Paths

Pick one path. Path A is recommended for this project.

Path A — All-in-WordPress RECOMMENDED

Everything lives inside WordPress. One login. One database. No monthly SaaS fees.

Stack

  • FluentCRM — CRM, knows every Woo customer automatically
  • Fluent Support — ticketing, talks to FluentCRM
  • FluentSMTP + Mailgun/SendGrid free tier — email

✅ Pros

  • One login, one database, no Zapier middleman
  • ~$258/yr total CRM cost
  • Native Woo integration (no sync issues)

❌ Cons

  • Less powerful than HubSpot/Salesforce at huge scale

Path B — External CRM Bridge

For if the client insists on a brand-name CRM (HubSpot, Pipedrive, Salesforce).

Stack

  • HubSpot (free tier) or Pipedrive as the CRM
  • Zapier or Make.com ($20/mo) to sync Woo orders → CRM
  • Communication via HubSpot inbox or Intercom

✅ Pros

  • More powerful pipeline / marketing tools
  • Brand-name client confidence

❌ Cons

  • Monthly cost ($20–$50+/mo for Zapier alone)
  • Two systems to maintain
  • More failure points (sync delays, API limits)
💡 My recommendation: Path A For a business-formation service with structured workflows, FluentCRM + Fluent Support is purpose-built and dramatically cheaper. You can always add HubSpot later if the client outgrows it.

⚠️ The 8–15% You Can't Fully Automate

These items look like they should be automatic, but no public API exists. Sell them as "managed by BizJump's filing team" — that's how every competitor works.
What the client expects to be automaticRealitySolution
Filing Status updates (Preparing → Filed → Approved) No state Secretary of State has a public API for this Admin marks status when team files — same as Northwest, Bizee, Incfile
EIN Status IRS does not expose an API Admin marks "In Progress" when applied, "Completed" when EIN received
Auto-generated compliance deadlines per state 50 states × multiple entity types — no central database One-time content task: hand-curate state requirements (~1 day research). Stored as templates that auto-populate based on user's state + entity type
Document auto-generation (Articles, Operating Agreement) Possible with WP Form-to-PDF plugins Add as optional later phase. Legal accuracy is the client's responsibility either way

🎯 What to Pitch the Client

Suggested framing — protects you from scope creep and matches reality.
📣 Recommended message "We'll deliver a fully functional dashboard that matches 92%+ of your spec using the WordPress / WooCommerce stack. The remaining 8% that requires real-time API integration with the IRS or state agencies (filing status, EIN status) will be admin-managed — your team marks status as filings progress, the same way Northwest, Bizee, and Incfile operate. This is industry-standard and gives you full control over what customers see."

Why this framing works

  • Honest — you're not promising magic that can't be delivered
  • Reassuring — naming competitors who do the same thing normalizes the limitation
  • Empowering — "you have full control" reframes the limitation as a feature
  • Scope-protecting — sets a clear boundary on what's in/out of v1
